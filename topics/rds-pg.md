# TCP Facts 2026-10-12: rds-pg

- On RDS for PostgreSQL, session_replication_role is an instance-level parameter, so one change plus a configuration reload applies to every database on that instance. (KB-37XS, live, checked 2026-02-04)
- During a DRS sync into RDS for PostgreSQL the destination instance runs with session_replication_role set to replica, which suppresses foreign key enforcement and user-defined triggers. Enforcement resumes when the parameter is set back to origin. (KB-3ADW, docs, checked 2026-09-25)
- A major version upgrade of RDS for PostgreSQL creates a new DB instance and keeps the original, which stays billed until it is released. Rollback is impossible, and read replicas and DR instances are left out of the upgrade and have to be created again. (KB-44WY, docs, checked 2026-09-25)
- The state of the pre-check or the upgrade is read with GET .../major-version/status?action=check or action=upgrade (running, success or failed). Past runs are listed with GET .../major-version/inspection-histories and GET .../major-version/upgrade-histories. (KB-6CHD, docs, checked 2026-09-25)
- Incremental DDL synchronization in a DRS PostgreSQL task needs the hwdrs_ddl_info table, the hwdrs_ddl_function() function and the hwdrs_ddl_event event trigger on the source plus the Incremental DDLs option. Table-level object selection syncs only TRUNCATE, DROP TABLE and ALTER TABLE; database-level selection adds CREATE SCHEMA and CREATE TABLE, CREATE, ALTER and DROP of sequences and indexes plus CREATE VIEW and ALTER VIEW. (KB-AG4T, docs, checked 2026-09-25)
- The DRS documentation has the user set session_replication_role to replica on the destination RDS for PostgreSQL instance before an incremental sync of objects with foreign keys, triggers or event triggers (a pre-check item) and back to origin after the sync; until then it stays replica. In replica mode foreign key constraints are not enforced and triggers do not fire; on RDS the parameter lives in the instance parameters, so it covers every database of the instance. (KB-CLJI, docs, checked 2026-09-25)
- On 2026-09-25 GET .../major-version/available-version with a made-up instance id answered the RDS error DBS.200002 (RDS instance not found) in eu-de and eu-nl, while an unknown path under the same prefix answered APIGW.0101, so the major version API is published in both regions. (KB-ESYW, live, checked 2026-09-25)
- The DRS DDL-sync trigger function is SECURITY INVOKER: it writes to public.hwdrs_ddl_info as the user who runs the DDL, reads the table and takes ids from its sequence. The DRS procedure grants SELECT, INSERT and DELETE on the table, SELECT and USAGE on the sequence and EXECUTE on the function to PUBLIC; without such grants DDL by other users fails with permission denied. (KB-G7PE, docs, checked 2026-09-25)
- A CES metric query for an RDS for PostgreSQL node takes the node ID, not the instance ID, in the dimension dim.0=postgresql_instance_id,{node_id}. (KB-IZ5Q, docs, checked 2026-09-25)
- The API reference pages in the docs mirror name only RDS for PostgreSQL 13 (13.3 or later) and 14 (14.4 or later) as upgradable sources, while the user guide page on the console upgrade names 12.7 or later, 13.3 or later, 14.4 or later, 15.4 or later, 16 and 17, with targets up to 18. Both say OS restrictions exclude some instances and point to the list of available target versions (the available-version call, or the Major Version Upgrade page on the console). (KB-NGGJ, docs, checked 2026-09-25)
- For RDS for PostgreSQL, disk encryption covers the instance disk. Backup files stored in OBS stay outside that encryption scope. (KB-PB6D, docs, checked 2026-09-16)
- In a live DRS migration into RDS for PostgreSQL on 2026-02-04 the job copied data and schemas but no roles, and schemas whose owning role was missing on the destination ended up owned by root. The DRS documentation lists users in the sync scope from PostgreSQL to RDS for PostgreSQL when the source account can read pg_authid and the destination account has CREATEROLE. (KB-TDGZ, docs, checked 2026-09-25)
- Iceberg catalog options on TCP, as tested: the MRS Hive Metastore (tables register with table_type ICEBERG and HetuEngine reads them), a JDBC catalog on RDS PostgreSQL when there is no MRS cluster, and a Hadoop catalog on OBS, which upstream Iceberg advises only for a single writer. (KB-UDT3, live, checked 2026-07-28)
- A major version upgrade of RDS for PostgreSQL through the API runs GET /v3/{project_id}/instances/{instance_id}/major-version/available-version for the allowed targets, POST .../major-version/inspection with target_version for the pre-check, then POST .../major-version/upgrade. The upgrade needs a successful check report for the same source and target version made within the last seven days. (KB-XT4X, docs, checked 2026-09-25)
- POST .../major-version/upgrade also requires is_change_private_ip. With true the floating IP of the source instance moves to the new instance and statistics_collection_mode (before_change_private_ip or after_change_private_ip) becomes mandatory, with false the source keeps its IP and the new instance gets a new floating IP. (KB-YJPI, docs, checked 2026-09-25)
