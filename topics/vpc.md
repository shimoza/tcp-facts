# TCP Facts 2026-10-10: vpc

- Once the WAF engine port is gone, the security group and the subnet delete cleanly. A VPC delete can still answer 409 VPC.0104 once while the subnet settles and then succeed on the next attempt. (KB-3TES, live, checked 2026-09-16)
- The VPC api-ref requires a plain IP address for the ip_address of an allowed address pair under the hardware SDN networking plan, and a dedicated security group for a pair whose mask is shorter than /24. (KB-3YKZ, docs, checked 2026-06-12)
- Updating an existing subnet with primary_dns and secondary_dns is rejected with VPC.0201 'secondary_dns fail when primary_dns is empty', although primary_dns is in the body. An update that sets the dnsList array returns 200, and running guests pick it up on DHCP renew. (KB-4AB2, live, checked 2026-07-17)
- TCP security group rules are not allow-only. Each rule has an action of allow or deny and a priority, read through the v3 API, and deny rules exist live in eu-de (KB-OVQP). The FAQ that calls security groups a whitelist describes allow rules only. (KB-4DQW, docs, checked 2026-10-02)
- The VPC quota and its used count for a project are returned by GET /v1/{project_id}/quotas with type vpc. (KB-4DTY, live, checked 2026-07-17)
- In the VPC API a subnet's id and its neutron_subnet_id are two different values; the subnet id equals its neutron_network_id. A port references both: its network_id holds the VPC subnet id and its fixed_ips subnet_id holds the neutron_subnet_id (neutron_subnet_id_v6 for an IPv6 address) (eu-de, checked 2026-09-25). (KB-4N3E, live, checked 2026-09-25)
- In eu-de a single VPC is read with GET /v1/{project_id}/vpcs/{vpc_id}. The response wraps the object under the singular key vpc, while the collection call returns the list under vpcs. (KB-4NWB, live, checked 2026-09-25)
- A subnet created over the API takes DNS server addresses and dhcp_enable as explicit fields. The values the API applies when those fields are omitted differ from the ones the console sets for a subnet. (KB-55UQ, live, checked 2026-08-18)
- The description of a security group rule is free text of up to 255 characters without angle brackets and is independent of the rule body. Whether a rule allows or denies is in its action field (allow or deny, default allow), which the v3 API returns and the v1 and v2.0 reads do not, so a rule read back as protocol null and remote_ip_prefix 0.0.0.0/0 matches all IPv4 traffic in its direction but is an allow-everything rule only if the v3 API shows action allow (eu-de, checked 2026-09-25). (KB-5TKG, docs, checked 2026-09-25)
- A VPC subnet in eu-de with no servers still carries two system ports in GET /v1/{project_id}/ports: device_owner network:dhcp with an empty device_id, and network:router_interface_distributed whose device_id is the VPC id. A check for leftovers before deleting a subnet can ignore those two owners. (KB-6FJO, live, checked 2026-10-05)
- A VPC subnet accepts masks down to /29: on 2026-09-25 in eu-de a /29 and a /28 subnet were created and turned ACTIVE. A /30 create answered HTTP 200, but the subnet never turned ACTIVE and was gone within a minute. The VPC user guide says /29, the API reference says the mask cannot be greater than 28, and the live result follows the user guide. (KB-7ISN, live, checked 2026-09-25)
- dhcp_enable has to be true on a VPC subnet for cloud-init in the guest to get an address and inject the SSH key. With it false the instance comes up without an address. (KB-7MAW, live, checked 2026-08-18)
- An unfiltered GET /v2.0/ports?limit=500 returned a body with no ports key at all. (KB-7NBH, live, checked 2026-09-16)
- Subnet delete uses the nested path DELETE /v1/{project_id}/vpcs/{vpc_id}/subnets/{subnet_id}, while create posts to the flat path /v1/{project_id}/subnets. (KB-7RKE, docs, checked 2026-08-18)
- Intra-subnet ICMP ping failed where the security group carried only a rule with no protocol set, while TCP over the same path worked. The VPC user manual lists All, TCP, UDP, GRE and ICMP as Protocol values. The observation and the manual disagree and no re-test has been made. (KB-ANXW, live, checked 2026-09-02)
- A subnet created with POST /v1/{project_id}/subnets without DNS fields has an empty dnsList, so guests get no DNS resolvers: traffic by IP works, name resolution fails. The console fills in default resolvers, the API does not. Pass primary_dns and secondary_dns when creating subnets by API or IaC. (KB-BANM, live, checked 2026-07-17)
- Security group rules on TCP carry an action of allow or deny with a priority from 1 to 100, which only the v3 API returns. Traffic that matches no inbound rule is denied implicitly. Deny rules exist live in eu-de (KB-OVQP). Network ACL and firewall rules have their own allow and deny actions. (KB-BNGZ, docs, checked 2026-10-02)
- A VPC subnet gateway address is a settable field under Advanced Settings at subnet creation, where the .1 address is only the example. It is fixed once the subnet exists. (KB-BY5T, docs, checked 2026-08-26)
- The VPC user guide calls the subnet-level stateful allow and deny ACL a Firewall, while the VPC v3 API names the same object network_acl. (KB-BZZQ, docs, checked 2026-06-08)
- A VPC port has source and destination checking on by default, so an appliance routes or NATs traffic only after the check is disabled on every transit NIC, which is done by adding a wildcard allowed-address-pair entry to the port. (KB-C4X3, live, checked 2026-07-23)
- A VPC create is polled to status OK and a subnet create to status ACTIVE before the next resource in the chain is created. (KB-D2OW, live, checked 2026-08-18)
- In eu-de the VPC listing is GET /v1/{project_id}/vpcs and returns the networks under the response key vpcs. Each entry carries id, name, cidr and status. (KB-DR57, live, checked 2026-09-25)
- opentelekomcloud_vpc_subnet_v1 exposes two different ids: .id is the VPC subnet id, while .network_id is the value that NAT gateways, CCE, ELB, RDS and SFS expect. Passing the wrong one fails late and reads like a permission problem. (KB-DYU2, live, checked 2026-09-16)
- A single security group rule is removed with DELETE /v1/{project_id}/security-group-rules/{rule_id} on the VPC v1 API in eu-de, which answers HTTP 204. (KB-EVGE, live, checked 2026-06-08)
- When a VPN route for a CIDR already exists, creating a VPC subnet with that CIDR returns HTTP 200 and the route table then holds a local and an eni route for the same destination, with no error or warning. This contradicts the documented rule of one route per destination. (KB-F44Z, live, checked 2026-08-26)
- The VPC of a resource is read from a different field per service: ECS metadata.vpc_id, CCE spec.hostNetwork.vpc, ELB vpc_id, NAT gateway router_id, RDS vpc_id. An EIP is matched over its load balancer or over the private address inside the VPC CIDR. (KB-F5QT, live, checked 2026-09-17)
- VPC peering judges overlap on the declared VPC CIDR, not on the subnets in use. Two VPCs whose declared ranges overlap cannot be connected by a peering connection, and the documentation answer is to replan the network. (KB-FD3K, docs, checked 2026-09-16)
- VPC quota can be read before a create with GET /v1/{project_id}/quotas?type=vpc on vpc.eu-de.otc.t-systems.com. The 200 response carries quotas.resources[] entries with type, used, quota and min. (KB-GAQV, live, checked 2026-08-18)
- A newly created security group already carries an egress allow-all rule and an ingress rule for members of the same group. (KB-GRIL, live, checked 2026-08-18)
- Creating a VPC subnet whose CIDR duplicates an existing VPN route returns HTTP 200 in eu-de, and the route table then stably holds that destination twice, once as local and once as eni, although the documentation states duplicate destinations are rejected. (KB-GSLG, live, checked 2026-08-26)
- A VPC peering between two VPCs of the same tenant becomes active on creation, without a separate accept step. Routes have to be added on both sides, in Terraform with opentelekomcloud_vpc_route_v2, type "peering" and nexthop set to the peering id. (KB-H7KG, live, checked 2026-09-16)
- The VPC API reference on TCP exposes no sub-network-interface endpoints. The VLAN-based supplementary network interface capability exists on the platform but is consumed by the CCE Turbo CNI only, so there is no customer-usable equivalent of ENI prefix delegation on ECS. (KB-HLIZ, docs, checked 2026-06-12)
- Two VPC route conflicts are rejected: creating a VPN connection whose peer subnet equals an existing VPC subnet returns VPN.0219, and adding a peering route for a destination already routed to a VPN returns 400 DestinationAlreadyExist. (KB-HNE7, live, checked 2026-08-26)
- The VPC v1 API lists security groups together with their rules at /v1/{project_id}/security-groups in eu-de, returning security_groups[].security_group_rules[]. Each rule carries id, direction, ethertype as IPv4 or IPv6, protocol where null means any, port_range_min, port_range_max, remote_ip_prefix and remote_group_id. (KB-IJZM, live, checked 2026-06-08)
- GET /v1/{project_id}/subnets also returns legacy neutron networks, recognisable by status UNKNOWN, scope center and a missing vpc_id field. A record without vpc_id is not a VPC subnet. (KB-KGJY, live, checked 2026-09-17)
- On T Cloud Public (TCP) in eu-de network ACLs are read with the VPC v3 call GET /v3/{project_id}/vpc/firewalls, which returns HTTP 200 with the response keys firewalls and page_info. (KB-KMWL, live, checked 2026-07-02)
- The VPC quota of a project is read with GET /v1/{project_id}/quotas against the VPC endpoint in eu-de. The response carries one record per type, for example type vpc with a used and a quota value. (KB-KQ3Z, live, checked 2026-08-26)
- A subnet created with POST /v1/{project_id}/subnets and no DNS fields ends up with an empty dnsList, and its instances get no resolver. The console fills in the regional resolver addresses, the API does not. (KB-KS3J, live, checked 2026-07-17)
- A port whose device_owner still points at an already deleted VM blocks deletion of its subnet and VPC, and a tenant cannot remove such a port itself. Clearing it required a support ticket to force-delete the stale port or the VPC. (KB-KZJU, docs, checked 2026-09-25)
- A VPC subnet is created with dhcp_enable true by default. (KB-L6FG, docs, checked 2026-08-18)
- A security group rule is added with POST /v1/{project_id}/security-group-rules and removed individually by rule id with DELETE on the same path. A newly added rule takes a few seconds to become effective. (KB-LERK, live, checked 2026-07-29)
- In allowed_address_pairs a pair whose prefix is /0 with any non-zero address is accepted as the any-source wildcard, while a literal 0.0.0.0/0 is rejected by request validation. (KB-LSXG, live, checked 2026-07-23)
- In a bridge VPC, /32 routes to each source database address over cross-tenant VPC peering plus one /24 route to the destination VPCs over intra-tenant peering carry DRS traffic in both directions. Longest prefix match decides, and DRS replication instances receive addresses different from the source database. (KB-LTUU, live, checked 2026-02-04)
- After a persistent connection is cut, a new connection under the new rule only forms once the connection tracking entry has timed out: 600 seconds for established TCP, 30 seconds for TCP in FIN-WAIT and for ICMP, 180 seconds for other protocols with traffic in both directions and 30 seconds with traffic in one direction. (KB-LUT7, docs, checked 2026-09-25)
- Adding a VPC peering route for a destination already covered by a VPN route returns 400 DestinationAlreadyExist. (KB-LXWR, live, checked 2026-08-26)
- POST /v1/{project_id}/subnets leaves primary_dns and secondary_dns empty when the fields are omitted, while the console form prefills them. An instance on such a subnet reaches ACTIVE and answers SSH, and name resolution in the guest fails. (KB-MM4Z, live, checked 2026-08-18)
- A security group rule description is free text and does not define what the rule does: a rule with protocol null, no ports and a remote prefix covering all addresses matches all traffic in its direction and allows it only when its action is allow. The action (allow or deny, with a priority from 1 to 100) is returned by the v3 API but not by the v1 and v2.0 reads, so audits must read action, priority, protocol and remote_ip_prefix from the v3 API, never the description (eu-de, checked 2026-09-25). (KB-MOMQ, docs, checked 2026-09-25)
- A security group filters inbound traffic to an ECS while egress is open by default, so an outbound transfer from the instance to an external host over SSH runs without any security group change. (KB-MQP4, live, checked 2026-06-16)
- Subnets set up through the console in eu-de carry primary_dns 100.125.4.25 and secondary_dns 100.125.129.199, the platform resolvers. A subnet created through the API or Terraform should set both explicitly. (KB-N2BY, live, checked 2026-10-05)
- VPC firewall rule changes never cut existing connections: adding, changing or deleting a firewall rule and associating or disassociating a subnet leave all inbound and outbound persistent connections up. The new rules apply to new connections only. (KB-N6UD, docs, checked 2026-09-25)
- Every VPC route table carries system routes for 100.64.0.0/10 and 198.19.128.0/20 and a loopback route for 127.0.0.0/8. System routes cannot be modified or deleted. (KB-NLXW, docs, checked 2026-09-25)
- The default VPC quota per tenant is 10, and creating an eleventh VPC returns VPC.0114 OverQuota. Current use is readable with GET /v1/{project_id}/quotas, where the subnet quota is 100. Raising the VPC quota goes through a support request. (KB-NPZK, live, checked 2026-07-23)
- Traffic over an active VPC peering needs a route entry in the route table on each of the two sides, with the peer VPC CIDR, a peer subnet CIDR or a peer ECS IP address as destination. (KB-O6IU, docs, checked 2026-09-25)
- Security group rules on TCP are not allow-only. The v3 API and the console carry an action of allow or deny and a priority, and deny rules exist live in eu-de (KB-OVQP). The older FAQ wording on a whitelist mechanism and aggregated rules predates this and does not cover deny rules. Restricting egress can use a deny rule in the security group or another control such as Cloud Firewall, NAT or routes. (KB-OIUA, docs, checked 2026-10-02)
- A VPC peering whose two VPCs belong to different tenants becomes active only after the owner of the accepting VPC accepts the request. (KB-OOK5, docs, checked 2026-09-25)
- TCP security groups can hold deny rules. A live read of the v3 security group rules API in eu-de on 2026-10-02 returned two enabled ingress rules with action deny on one test tenant (priority 4 and 5, IPv4, all protocols) next to allow rules. The other test tenant held 205 rules, all allow. The v3 API returns action and priority on every rule. (KB-OVQP, live, checked 2026-10-02)
- The allow-any rule that references a security group's own id appears twice in a listing, once with ethertype IPv4 and once with IPv6. The two entries form one pair covering both address families, not a duplicated rule. (KB-PF6Q, live, checked 2026-06-08)
- Security groups track connections: a changed inbound rule applies to existing traffic at once, while outbound changes only affect new connections. Any added, changed or deleted rule and any instance added to or removed from the group clears the inbound persistent connections of all instances in the group, while outbound persistent connections stay. (KB-PI2D, docs, checked 2026-09-25)
- VPC peering connections are listed with GET /v2.0/vpc/peerings, a v2.0 path that carries no project id segment. The response key is peerings and each entry has name, status, request_vpc_info with vpc_id, and accept_vpc_info with vpc_id and tenant_id. (KB-PWJP, live, checked 2026-09-25)
- POST /v1/{project_id}/subnets stores primary_dns and secondary_dns as empty when the request omits them. The console prefills both fields, the API does not, so a subnet built by API or Terraform can hand out no resolver at all. The region resolver addresses have to be set explicitly. (KB-Q5W2, live, checked 2026-08-18)
- In eu-de two subnets deleted with DELETE /v1/{project_id}/vpcs/{vpc_id}/subnets/{subnet_id} were gone within seconds, their dhcp and router-interface ports included, and the VPC could be deleted right after. A GET on the deleted VPC answers 404 VPC.0105 with the Neutron message RouterNotFound, so a VPC is a Neutron router underneath. (KB-RD6U, live, checked 2026-10-05)
- GET /v2.0/ports?network_id={id} returned 0 ports for a subnet that held three ports, one of them attached to a running VM. The same call without the filter, matched client-side on network_id and on fixed_ips subnet_id, returned all three. (KB-SLWK, live, checked 2026-09-16)
- The resource opentelekomcloud_vpc_secgroup_v3 creates the IPv4 and IPv6 allow-all egress rules by itself. Declaring an additional catch-all egress rule on the same security group returns 409 VPC.9902 "Security group rule already exists" and stops the apply. (KB-VBVB, live, checked 2026-09-16)
- GET /v1/{project_id}/quotas returns the per-resource quotas of a project, including the VPC quota. On a test tenant in eu-de the call reported the VPC quota at 10 of 10 used. (KB-VCIT, live, checked 2026-08-18)
- On T Cloud Public (TCP) in eu-de a subnet object returned by the VPC v1 API can carry an optional availability_zone attribute (the AZ specified at creation) and omits the key when none is set (checked 2026-09-25). The value does not limit where the subnet can be used: a subnet is defined by its VPC and its CIDR range and is not bound to a single availability zone. (KB-VLGS, live, checked 2026-09-25)
- Anti-spoofing on a VPC NIC drops packets whose source or destination address differs from the NIC's fixed IP, which affects any routing, firewall or VPN gateway instance. It is opened per NIC with PUT /v2.0/ports/{port_id} on vpc.eu-de.otc.t-systems.com setting allowed_address_pairs, returning HTTP 200. (KB-W7H2, live, checked 2026-07-23)
- In eu-de the quota for type vpc returned by the VPC quota endpoint is 10 VPCs per project. (KB-WGTH, live, checked 2026-08-26)
- Subnets are AZ-agnostic: an ECS placed in eu-de-03 was created on a subnet labelled eu-de-01 without problems. (KB-XGKU, live, checked 2026-07-20)
- A VPC create in a project that has reached its VPC quota fails with a quota error, not with a syntax or validation error. (KB-Y72H, live, checked 2026-08-18)
- The description of a security group rule is free text and has no effect on filtering. A rule described "Deny all traffic" with protocol All, port range 0 to 0 and remote_ip_prefix 0.0.0.0/0 is an ordinary allow-all rule. (KB-YGSM, docs, checked 2026-09-02)
- A VPC route table on T Cloud Public (TCP) cannot hold two routes with the same destination, even when the next hop types differ, and the system route created for a VPC subnet CIDR cannot be modified or deleted. (KB-YHLQ, docs, checked 2026-08-26)

- In the opentelekomcloud Terraform provider 1.37.8, opentelekomcloud_vpc_secgroup_rule_v3 uses the argument names ether_type and multi_port, carries an explicit action field, and takes a port list or a range in one field. The v2 spellings ethertype and multiport are rejected by terraform validate, and port_range_min and port_range_max are absent from the v3 schema. (KB-ZULT, live, checked 2026-09-16)
