# TCP Facts 2026-10-28: waf

- Dedicated WAF has resources dedicated per instance, can be spread over up to three availability zones and is reached through an internet-facing ELB. It comes as Professional WI-100 with 100 Mbit/s and 2,000 QPS or Enterprise WI-500 with 500 Mbit/s and 10,000 QPS, each with 60,000 WAF-to-server connections. (KB-2SIL, contract, checked 2026-10-14)
- When a protected domain is added in Cloud WAF with POST /v1/{project_id}/waf/instance, the certificate is referenced by the field certificate_id in snake_case. The spellings certid, cert_id and certificateid each returned WAF.1001 "invalid request". (KB-5A7O, live, checked 2026-05-26)
- From 1 October 2026 Classic Mode gets no regular updates, patches or bug fixes. Technical support continues on a best-effort basis without any obligation to provide bug fixes or security patches and continued operation is at the customer's own risk. (KB-BKQH, contract, checked 2026-10-14)
- The table in section 3.9.6 gives Cloud Mode the same metrics as Classic Mode: 300 Mbit/s, 10,000 QPS and 6,000 WAF-to-server connections per domain name. Classic Mode is connected by a CNAME DNS record change, while the access mode cell via internet-facing ELB spans both the Dedicated and the Cloud rows. (KB-BLS4, contract, checked 2026-10-14)
- Web Application Firewall (Dedicated) (WAF) is a web application firewall whose resources are dedicated per instance: it monitors, filters and blocks HTTP and HTTPS traffic to web servers with customer-set policies and logging, can be spread over up to three availability zones and is reached through an internet-facing Elastic Load Balancer. The Regions and Endpoints page lists API endpoints for dedicated WAF in eu-de and eu-nl. (KB-CE5J, contract, checked 2026-10-14)
- WAF events are listed with GET /v1/{project_id}/waf/event on waf.eu-de.otc.t-systems.com, with the from and to parameters given in epoch milliseconds; the API reference pages with offset and limit (and marker), while a live test on 2026-02-04 used pageindex and pagesize. The response key is items next to total, and each event holds id, host, url, rule, action, sip, payload and time. (KB-D4HX, docs, checked 2026-09-25)
- After a dedicated WAF domain is deleted, the engine port named WAF_ENGINE_<id> with device_owner compute:<az> stays ACTIVE in its subnet. While it is there, deleting the security group returns 409 VPC.0602 SecurityGroupInUse and deleting the subnet returns 409 VPC.0209. (KB-ELHG, live, checked 2026-09-16)
- Dedicated WAF accepts POST /v1/{project_id}/waf/policy without a WAF instance in eu-de (HTTP 200) and deletes such a policy with HTTP 204. A global protection whitelist rule on such a policy was refused with WAF.1001 on 2026-09-25, even with the documented example body. (KB-GA75, live, checked 2026-09-25)
- A WAF ignore rule for a false alarm needs the event_id field in the request body next to the path; the API reference marks both as mandatory and gives the rule back only in the response. A body sent without event_id was answered with HTTP 400 Bad request in a live test on 2026-02-04. (KB-JADS, docs, checked 2026-09-25)
- Web Application Firewall (Cloud Mode) (WAF) monitors, filters and blocks HTTP and HTTPS traffic to web servers; the customer creates, configures and monitors it, activates protection policies and logs their activity. The documentation names protection against SQL injection, cross-site scripting, web shells, command and code injection, file inclusion, CC attacks, malicious crawlers and CSRF, and a Cloud Mode instance provides the ELB access mode, in which WAF inspects traffic inside the gateway of a dedicated application load balancer (KB-TJGQ). Cloud Mode is generally available in eu-de and eu-nl since 3 March 2026 (KB-KFC4). (KB-K346, contract, checked 2026-10-14)
- T Cloud Public (TCP) offers a web application firewall as Web Application Firewall in Cloud Mode and in Dedicated Mode: it monitors, filters and blocks HTTP and HTTPS traffic to web servers with customer-set protection policies and logs its activity. Dedicated Mode has its own resources per instance across up to three availability zones and is reached through an internet-facing load balancer. (KB-KIAP, contract, checked 2026-10-14)
- DELETE /v1/{project_id}/waf/instance/{domain_id}?keepPolicy=false returns 204 and removes the WAF domain together with its bound policy. A separate delete of that policy afterwards answers 404 WAF.3001. (KB-KJ6E, live, checked 2026-09-16)
- POST /v1/{project_id}/waf/certificate on waf.eu-de.otc.t-systems.com returns WAF.1605 "invalid certificate content format" for a well-formed multi-line PEM. With every newline removed from the certificate content and from the private key, the same request returns 200 and a certificate id. (KB-KYXU, live, checked 2026-05-26)
- On 2026-09-25 the Classic WAF API on waf.eu-de still answered GET /v1/{project_id}/waf/instance. The dedicated WAF API answers on its own endpoint premium-waf.eu-de and its path /v1/{project_id}/premium-waf/instance is not served on waf.eu-de. (KB-LAFN, live, checked 2026-09-25)
- WAF Dedicated host create names the same certificate reference certificateid, without the underscore, so a request body that works for Cloud WAF carries the wrong field name for Dedicated. (KB-MNON, docs, checked 2026-09-25)
- On eu-de no tenant API removes a dedicated WAF engine after its domain has been deleted. (KB-NAYN, live, checked 2026-09-16)
- An ec-256 ECDSA certificate returned WAF.1605 from the Cloud WAF certificate upload even after the newlines were stripped, while an RSA certificate sent the same way was accepted. (KB-NQ7B, live, checked 2026-05-26)
- The WAF API reports the protection state of a domain in the field protect_status, where 0 means protection is off, 1 means protection is on and -1 means WAF is bypassed. (KB-OJXA, docs, checked 2026-09-25)
- The successors of Classic Mode are Cloud Mode and Dedicated Mode. The service description names Cloud Mode as its strategic replacement and the release notes of 1 June 2026 recommend starting the migration now. (KB-ORQX, contract, checked 2026-10-14)
- A WAF ignore rule is created with POST /v1/{project_id}/waf/policy/{policy_id}/ignore on waf.eu-de.otc.t-systems.com. The API reference lists path and event_id as the body fields, both required, and returns rule, event_type and the id of the new masking rule in the response. (KB-OX3H, docs, checked 2026-09-25)
- Web Application Firewall - Modes and Metrics (WAFMM) sets the access modes and capacity of the WAF offers: the classic shared mode is connected by a CNAME DNS record change, while the access mode cell via internet-facing ELB spans the Dedicated and Cloud rows (KB-BLS4). Cloud Mode handles 300 Mbit/s, 10,000 QPS and 6,000 WAF-to-server connections per domain name; Dedicated Mode comes as Professional WI-100 (100 Mbit/s, 2,000 QPS) or Enterprise WI-500 (500 Mbit/s, 10,000 QPS), each with 60,000 WAF-to-server connections. (KB-PMPA, contract, checked 2026-10-14)
- The WAF event list endpoint /v1/{project_id}/waf/event takes the from and to window as epoch milliseconds and pages its result with offset and limit per the API reference (pageindex and pagesize were used in a live test on 2026-02-04). The event_id that an ignore rule requires is taken from this list. (KB-SQUD, docs, checked 2026-09-25)
- Event IDs for a WAF ignore rule come from `GET /v1/{project_id}/waf/event?from={ms}&to={ms}`, which takes the time window as millisecond timestamps. (KB-SVH6, docs, checked 2026-09-25)
- A Cloud Mode instance provides the ELB access mode of WAF: WAF is built into the gateway of a dedicated load balancer with an application (HTTP/HTTPS) specification, inspects the traffic there and does not forward it itself. (KB-TJGQ, docs, checked 2026-09-25)
- WAF Classic Mode is no longer bookable from 1 June 2026 and reaches End-of-Maintenance and Support on 1 October 2026. (KB-WNNJ, contract, checked 2026-10-14)
- The WAF ignore rule call POST /v1/{project_id}/waf/policy/{policy_id}/ignore requires path and event_id in the body per the API reference, which lists rule only as a response field. A body without event_id returned HTTP 400 Bad Request in a live test on 2026-02-04. (KB-YECU, docs, checked 2026-09-25)
