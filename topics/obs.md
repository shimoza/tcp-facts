- Uploading a large directory to OBS with obsutil from a 4 vCPU ECS in eu-de lost 3 of 81 parts to TCP drops at parallelism 16. The same upload at parallelism 8 finished with no failed parts. (KB-QDQE, live, checked 2026-05-01)
- A multipart upload to OBS is limited to 10000 parts of 100 KB to 5 GB each (only the last part may be smaller), so the part size must be at least the object size divided by 10000. A 142 GiB object at 128 MiB parts uses 1136 parts. (KB-QLRN, docs, checked 2026-09-25)
- OBS object-lock retention covers only objects uploaded after the policy is set, and uploading the same key again creates a new current version that sits outside the protection. (KB-R7FC, docs, checked 2026-09-01)
- A bucket-level OBS request must go to the endpoint of the bucket's own region: a bucket created in eu-de returned 404 NoSuchBucket through the eu-nl endpoint. ListBuckets answered through either regional endpoint. (KB-RLOL, live, checked 2026-09-15)
- On TCP, OBS parallel file systems do not support server-side encryption: the PFS feature guide (release 2026-06-23) lists it as a constraint and marks the bucket encryption APIs as not compatible. For SSE-KMS, OBS bucket default encryption takes SSEAlgorithm kms with an optional KMSMasterKeyID and ProjectID and has no BucketKeyEnabled setting. (KB-RM33, docs, checked 2026-09-25)
- OBS V2 signing includes the query sub-resource in the canonical resource string. A request to GET /?storageinfo signed without it returns HTTP 403 SignatureDoesNotMatch in both path and virtual-host style, while a plain listing of the same bucket with the same key succeeds. (KB-RT73, live, checked 2026-09-16)
- An upload of about 400 GB spread over 81 objects, sent from an ECS to an OBS bucket in the same region, took roughly 65 minutes. (KB-S4QM, live, checked 2026-05-01)
- OBS bucket notification event names are written without the s3: prefix. ObjectCreated:* is the accepted form. (KB-SAM5, live, checked 2026-08-27)
- Copying 81 files of about 5 GB each to OBS with `obsutil cp -r -p 16` from a 4 vCPU host failed on 3 files with `write tcp: use of closed network connection` and exit code 8. The targeted retries with `-p 8` finished without a failure. (KB-SD7O, live, checked 2026-05-01)
- An OBS bucket without a bucket policy is closed to other accounts by its private ACL only. Inside the owning account every IAM user whose IAM permissions allow OBS reaches it, because ACLs do not control the IAM users of that account. Only an explicit Deny in a bucket policy overrides such an IAM allow. (KB-SPIK, docs, checked 2026-09-23)
- A WORM-protected OBS object can have its storage class changed by a lifecycle rule while the retention lock still blocks deletion of the object. (KB-SQDE, docs, checked 2026-09-02)
- OBS Cold storage restore has three documented speeds: Expedited 1 to 5 minutes, Standard 3 to 5 hours and Bulk 5 to 12 hours. (KB-SSWP, docs, checked 2026-09-02)
- The system-managed obs/default key, like evs/default, cannot be granted to another tenant. Either the data is decrypted first or a custom CMK is used. (KB-T4BR, docs, checked 2026-09-25)
- An OBS object in the Cold (GLACIER) class has to be restored to STANDARD before it can be read, copied or re-encrypted. The S3-compatible restore request takes a number of days and a retrieval tier; a HEAD on the object reports Restore ongoing-request="false" once the copy is ready. (KB-TA3K, docs, checked 2026-09-25)
- On OBS, WORM retention on a bucket and cross-region replication of that bucket are mutually exclusive, per the OBS documentation. (KB-TA6I, docs, checked 2026-09-01)
- The default storage class of an OBS bucket is set with PUT on the bucket URL with the ?storageClass sub-resource and an XML StorageClass body naming STANDARD, WARM or COLD, and read back with GET ?storageClass. The IAM action is obs:bucket:PutBucketStoragePolicy. (KB-TD5E, docs, checked 2026-09-25)
- Object Storage is billed with a cumulative graduated price: the price scales are filled one after another and each part of the used quantity is billed at its own scale. Taking the single tier a volume lands in and multiplying the whole volume by that rate over-states the bill. (KB-TPA7, contract, checked 2026-08-27)
- An IAM user reaches one OBS state bucket through a bucket policy naming the principal as domain/<domain_id>:user/<user_id>, with no OBS role assigned at all. A second bucket in the same account stayed denied for that user. (KB-TQIX, live, checked 2026-09-17)

- OBS ignores the conditional If-None-Match header on PUT through its S3-compatible API, so a write that should fail when the object already exists overwrites it instead. (KB-UHIV, live, checked 2026-07-17)

- To pin a specific custom CMK as the bucket default encryption on OBS, the PUT ?encryption body carries KMSMasterKeyID inside ApplyServerSideEncryptionByDefault next to SSEAlgorithm kms. Without that element the default key obs/default is used, and the documented success response is HTTP 200. (KB-VOUX, docs, checked 2026-09-25)
