# TCP Facts 2026-11-09: pricing

- The price API returns rows for flavors marked sellout in cond:operation:az and for ramped-down services. Orderability follows from the per-AZ state, not from the presence of a price row. (KB-4ABK, live, checked 2026-09-25)
- No public service description of the Swiss offering (eu-ch2) was found on 2026-10-08: the TCP service description revision 17.08.2026 covers EU-DE and EU-NL only, the Swiss product pages link that same general document, and the operator's Swiss site offers a price calculator in CHF and a technical flyer of 2022 but no service description or price list. What is offered in eu-ch2 has to be confirmed with the Swiss entity before it is quoted. (KB-4FW6, docs, checked 2026-10-08, recheck due)
- Answers of the public price API can carry response.cachedAt, the time of a server cache in server time, two hours ahead of UTC on 2026-09-24. That day an unfiltered query answered from a cache of 2026-09-07 and a query for sn=ecs from one of 2026-09-17, so a price read today can come from a cache more than two weeks old. (KB-5LLN, live, checked 2026-09-24)
- On 2026-10-14 the TCP price API, serving its cache of 2026-10-10, gave the 4- and 8-GPU p5s (H100 PCIe) sizes a lower per-GPU open Linux rate than the 1- and 2-GPU sizes, as the list before 2026-09-10 did. The single per-GPU rate the API carried on 2026-09-10 now sits in the p5s rows of the service description revision 09.10.2026 instead. (KB-5RCL, live, checked 2026-10-14)
- A price API result for one sn can contain records of another product: the sn=dc result for rn=eu-de carried one stray DAS row, distinguishable by its productName field. (KB-6A7H, live, checked 2026-08-25)
- In the c9 price table of the TCP service description the flavour name is printed on the Oracle row, and the open Linux row directly above it carries its rate without a flavour name. A search combining a c9 flavour name with the words open Linux matches nothing. (KB-6HHT, contract, checked 2026-09-11)
- The TCP price API returns rows for services that are no longer offerable. By 2026-09-02 this had been observed for SFS Common I/O, BMS and DIS, so a price-API hit alone does not show that a service can be ordered. (KB-7VPP, live, checked 2026-09-24)
- Every record of the public price API has an id, a SKU code, while opiFlavour is empty on some: in eu-de on 2026-09-24 on 11 of 461 rds records, 1 of 11 eip records and 6 of 27 coss records. Every ecs, deh, obs, elb and nat record carried one. The id is the key to look a record up by. (KB-AEVL, live, checked 2026-09-24)
- In the TCP service description the commercial limit per business partner (section 3.1.1.1, footnote 2) and the footnote 1 marker for no guaranteed capacity are set only on the flexible-purpose families x1, x1e, x1m, x2, x2e, x2m and x2ne. The s9, m9 and c9 rows carry neither marker. (KB-AH5P, contract, checked 2026-09-11)
- The price API covers the s2, s3, s7n and s9 ECS families, so a flavor missing from the price API can still be listed in the service description catalog. (KB-AI2E, live, checked 2026-07-15)
- On the TCP price model page a Reserved package can be upgraded at any time to a larger instance type or a newer generation (for example c3 to c4 or s2 to c3) through the Service Desk. The term end stays the same: the time already used is billed to the day at the old rate (daily rate of the monthly price times the days passed) and the new package runs to the original end, also billed to the day. Reserved Upfront allows no such switch; it is billed as the full amount for 8,760 hours (365 days x 24 hours) at the end of the month of the order and then shows on each invoice without a charge. (KB-B2A7, docs, checked 2026-11-07)
- Under the TCP service description a Reserved or Reserved Upfront term of 12, 24 or 36 months needs an agreed minimum order volume. It is a monthly usage contingent for the selected flavor type, not fixed to one instance: one or several instances of that type use it, and it is billed even when it is not or not fully used. Use beyond the minimum order volume and all use after the term are billed in the Open Elastic model. (KB-B2JD, contract, checked 2026-11-07)
- A query of the price API that matches nothing answers HTTP 200 with stats.count 0 and result as an empty list, while a query that matches answers result as an object keyed by service name. A service name the API does not know answers HTTP 500 with code Error, so an empty answer and a refused query can be told apart. (KB-BVUH, live, checked 2026-09-24)
- The TCP price model page says Reserved is not available for every flavor and names terms of 12 or 24 months, while the service description of 09.10.2026 (the contract) names 12, 24 and/or 36 months. The price row of the flavor decides: the service description tables show n.a. and the price API shows zero for a term that is not offered, for example no 36-month term for g7v.2xlarge.8 in eu-de. (KB-COBA, docs, checked 2026-11-07)
- The TCP price API gives per record PAYG in EUR per hour, R12, R24 and R36 as the Reserved price in EUR per unit and month, and RU12, RU24 and RU36 as the Reserved Upfront total of the term divided by its months; zero means the term is not offered. The API page labels the fields without a unit; the service description lists Reserved in euro per month and Reserved Upfront as one euro amount for the whole term, and the API values match it that way for g7v.2xlarge.8 Windows in eu-de. (KB-DXYK, live, checked 2026-11-07)
- A price change is pre-announced inside the current revision of the service description. A section 6 price row can carry a "from DD.MM.YYYY:" subline: the value under the marker is the new hourly price, the value on the row above is the one in force until that date. (KB-FBVR, contract, checked 2026-07-05)
- Money values returned by the public price API use English number formatting: comma as thousands separator, dot as decimal separator, six decimal places, and the currency code appended after the value. (KB-FE6O, live, checked 2026-06-11)
- Windows ECS are priced in a separate, higher tier per flavor than the Open Linux tier: on 2026-09-24 the Windows rate was higher on all 306 flavors of the six ECS service names in eu-de that carry both. The OS of every VM decides which price row applies. (KB-FIBF, live, checked 2026-09-24, recheck due)
- Price rows in the service description can carry a "from <date>:" subline that announces a future value, so a parser reading only the main row returns the superseded value. (KB-FZRN, contract, checked 2026-07-01)
- The en variant of the price API writes every amount as a number with a decimal point, a comma as thousands separator and the currency code after it, while the de variant writes a decimal comma. A reader has to know which variant it reads, because a comma followed by three digits is ambiguous on its own. (KB-H5VQ, live, checked 2026-09-24)
- A pre-announced price change can move different rows by different ratios. In the change effective 01.07.2026, 81 of 90 affected ECS price points moved by factor 1.2500 and the nine s9 Windows rows by 1.1103, the compute and the Windows license component moving separately. (KB-HOSK, contract, checked 2026-07-05)
- A query to the TCP price API with sn=ucs returned HTTP 500 rather than an empty result set. (KB-HSN2, live, checked 2026-09-01)
- Reserved terms and discount depth are family-dependent: the 36-month term is offered for part of the ECS families. (KB-HSTO, live, checked 2026-09-25, recheck due)
- The unit field of the price API is free text with about 20 values, among them h, GB/month, Item/month, h/month and an empty unit. isMRC is true on some records whose unit is h, so neither field alone tells an hourly rate from a monthly one. (KB-HYBW, live, checked 2026-09-24)
- The service description lists flavor x1e.slarge.2 with 3 vCPU and 6 GB RAM, a specification the flavor name does not reflect. (KB-IDKJ, contract, checked 2026-07-01)
- The Financial Dashboard has a consumption view by tag with hourly and daily granularity and key/value selection, backed by the Business.tag_daily and Business.tag_hourly tables. Tagged resource costs appear in the invoice CSV. The invoice document stays per tenant and not every product is taggable. (KB-JDBN, docs, checked 2026-07-17)
- Ordering Reserved on TCP: it is ordered in the eShop or through Telekom Sales, and a booking through a sales contact or the Support Center needs a lead time of five working days before the term starts. Reserved is invoiced monthly and allows a switch to the next higher flavor or reserved class during the term; Reserved Upfront is invoiced for the whole term in the first month after provision and allows no switch. (KB-KM2G, contract, checked 2026-11-07)
- On the TCP price model page a Reserved term starts at 0:00 on the order day. A package ordered during a month is billed only for the rest of that month, and the last month is billed only for its part. Packages are not renewed automatically. The contingent of a month is the days of that month times 24 hours (summer and winter time counted); the unused part of a month expires and cannot be used later in the term. (KB-LWOH, docs, checked 2026-11-07)
- Open conflict on TCP, open with Telekom Sales since 2026-11-07: the price model page for computing says GPU flavors are billed also when stopped, while the service description (revision 09.10.2026, section 6.1.1) lists only i3, d2 and all Dedicated Host types as billed when stopped and the ECS documentation says a stopped G6, G7, G7v or P5e is billed only for its disk. Until Telekom Sales answers, price by the service description and the ECS documentation, and say so on every GPU line. It matters most for GPU machines that run part time: if stopped GPU flavors were billed, each would cost a full month by the hour and the part-time pay-per-use model would not hold. A lab run cannot settle it; it needs a written statement of the Service Desk or Telekom Sales, or the Financial Dashboard of a tenant whose stopped GPU machine was billed. (KB-NAAF, docs, checked 2026-11-07)
- The public price API returns money values in English number format: a comma separates thousands and a dot separates decimals, followed by the currency code. A parser that reads the comma as a decimal separator returns values a thousand times too low. (KB-NCPE, live, checked 2026-06-11)
- How to price Reserved on TCP: count the pooled hours of all instances of one billing item (flavor plus operating system) in a month, not the hours of each instance. The unit count is booked for the whole term, so choose it once against the months of the term; in each month n units cover n times the hours of that month and the rest runs Open Elastic. One more unit pays off when the rest of a month is above the monthly Reserved price divided by the hourly Open Elastic price of the same item. Use the real month length or state the 730-hour average, since Reserved is a flat monthly amount and a short month lowers the saving. Show the agreed minimum order volume as an open point on every reserved line, and a term the price row does not offer as not offered. (KB-NPRJ, docs, checked 2026-11-07)
- The price API switches to the announced value on the effective date. For the flavor families the API covers, the from-column of the service description and the API value agree to six decimals. (KB-PL7K, live, checked 2026-07-05)
- The eu-ch2 slice of the public TCP price API is not the Swiss price list: on 2026-10-08 it held 75 records marked EUR, 15 of them (KMS API calls, the five OBS Standard Space tiers, eight SMN rows) with exactly the numbers the Swiss calculator shows as CHF, and 60 rows that the Swiss calculator does not carry at all (API Gateway, HSS, WAF domain, FunctionGraph, LTS, DNS queries, OBS cold and warm space, outbound traffic, a firewall and VPN row), most of them priced zero. It carries no ECS, EVS or RDS row for eu-ch2, and its values were unchanged between 2026-09-24 and 2026-10-08. (KB-PRGT, live, checked 2026-10-08, recheck due)

- In the price API, sn=ecs covers only the s2, s3, s7n and s9 families. The vss.* entries in that payload are EVS disk SKUs rather than a compute family, and the other ECS families sit under other service names of the price API. (KB-RMW2, live, checked 2026-09-24)
- The price API returns rows and the documentation mirror keeps full user guides and API references for services that are no longer offered, VBS and CSBS (end of life since 01.01.2026) among them, so presence in either source does not show that a service is orderable. - In the public price API the service name sn=dcaas returns HTTP 500, while sn=dc with rn=eu-de returns the full Direct Connect price list including bandwidth tiers and ports. The same service can be served under an abbreviation different from the one used elsewhere. (KB-SEDA, live, checked 2026-08-25)
- On TCP each kind of VM (flavor plus operating system) is one billing item: the usage of the single VMs is recorded per second, summed over the calendar month and billed in hours, so several Windows VMs of one flavor add up in one item. A flavor with Windows and the same flavor with Linux are separate items, but several VMs of one flavor with different open Linux derivatives are not separated. A Reserved package draws on one such item. (KB-SFB4, docs, checked 2026-11-07)
- The public price API returns a changing set of ECS records: 502, then 508, then 400 within one month, with the x1 family and the s3 R36 reserved fields disappearing between calls. (KB-SFUF, live, checked 2026-07-01)
- The TCP service description, revision 09.10.2026, sets a compensation of half of the remaining payments for ending a reserved package before its minimum term (for reserved upfront: the pro-rata residual value), but the rule sits in section 7.2.6.2 under the special conditions for migration under the Data Act; no general early-end rule was found outside that section. (KB-SHDM, contract, checked 2026-10-22)
- Reserved price rows can be left out of a pre-announced increase. In the change effective 01.07.2026 the R12, R24 and R36 cells carried no from-date marker and their values did not move. (KB-SUE5, contract, checked 2026-07-05)
- The TCP price model page for computing says a Reserved package is a monthly credit of days x 24 hours for one instance type, not tied to one instance: several instances of that type may use it for part periods in the same month, use beyond it is billed in the Elastic mode, and the unused part of a month expires. Its example: two s2.xlarge.8 instances run at the same time and the use beyond the monthly 672 hours is billed Elastic. (KB-UD2I, docs, checked 2026-11-07)
- The TCP price API and the contractual service description can carry different rates for the same flavor family. (KB-UVSS, live, checked 2026-10-14)
- A Reserved or Reserved Upfront booking on TCP is a billing contingent for a flavor type: it allocates no resources in the customer tenant and holds no capacity for a stopped instance. (KB-VCXP, contract, checked 2026-10-21)
