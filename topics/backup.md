# TCP Facts 2026-10-14: backup

- Veeam Backup & Replication ships no hypervisor plug-in for the OpenStack/KVM platform that TCP runs on, so nothing that needs hypervisor integration can be delivered through it there. (KB-2FA3, docs, checked 2026-09-25)
- The Veeam 13 Plug-in for Universal Hypervisor API supports only VergeOS and Platform9, whose vendors built the integration. Platform9 is OpenStack based, so Veeam can cover an OpenStack platform this way, but no such plug-in exists for TCP. (KB-2IMZ, docs, checked 2026-10-09)
- Veeam sizing guidance for an object-storage repository is roughly 250 TB per bucket, so a 2 PB repository on OBS is laid out over about eight buckets. (KB-2T3L, docs, checked 2026-09-02)
- Veeam Backup & Replication 13 exports disks from VMware vSphere and Hyper-V VM backups and from Veeam Agent backups to VMDK, VHD or VHDX, and it can write them to any server added to its backup infrastructure. (KB-6ACV, docs, checked 2026-10-09)
- A Veeam Backup & Replication 13 disk export in VMDK format writes two files, a descriptor and a content file, and outside an ESXi datastore the disk is thick provision lazy zeroed. A VHD or VHDX export writes one file, which fits the one-file-per-image import of IMS. (KB-BUR2, docs, checked 2026-10-09)
- The Veeam Backup & Replication 13 workloads list (updated 2026-07-31) names Amazon Web Services, Microsoft Azure and Google Cloud as the only public clouds and has no OpenStack entry, so TCP, like other smaller public clouds, is not on the official Veeam support list. (KB-C7WI, docs, checked 2026-10-09)
- Veeam Backup & Replication 13 application-aware processing needs VMware Tools in the guest OS of a VMware VM. So in a Veeam recovery to TCP the tools stay on the source VMs and are removed on the restored ECS, not before the backup. (KB-CEC6, docs, checked 2026-10-09)
- In AWS Backup only full-management resource types (S3, EFS, EKS and DynamoDB with advanced features) produce Backup-owned artefacts that restore into AWS only. EBS, RDS, Aurora, FSx and standard DynamoDB keep native snapshots with first-party export paths, including RDS snapshot export to Parquet in S3 and DynamoDB export to S3 as JSON or Ion. (KB-D6KV, docs, checked 2026-09-01)
- Veeam v13 Universal CDP protects virtual, physical and cloud guests with an in-guest agent, so continuous replication out of a TCP instance to an on-premises vSphere target works. The guest must use UEFI boot, GPT partitioning and a supported operating system. (KB-G66F, docs, checked 2026-09-02)
- The Veeam Backup & Replication 13 cmdlet Start-VBRRestoreVirtualDisks takes as -Server the Windows host to which the disks are exported, so a scripted disk export on TCP needs a Windows ECS as export target, although the user guide also accepts a Linux server for the console route. (KB-HMHD, docs, checked 2026-10-09)
- Veeam v13 documentation excludes bucket lifecycle rules on a bucket used as a Veeam object-storage repository, so tiering of that bucket is driven by Veeam rather than by an OBS lifecycle policy. (KB-KVWG, docs, checked 2026-09-02)
- After the Veeam backup server is lost, a new Veeam server reaches backups in an object storage repository once that repository is added and rescanned. The backups then show under Backups > Object Storage (Imported). (KB-LFZT, docs, checked 2026-10-09)
- Veeam Backup & Replication 13.0, from the Veeam Data Platform Premium 13.0 installer ISO dated 2026-03-10, installed and ran in standalone mode (backup server, proxy and repository on one host, bundled PostgreSQL configuration database, 30-day evaluation licence) on a Windows Server 2022 ECS built from the eu-de public image Enterprise_Windows-Server_2022_STD_amd64_bios_latest, flavor s3.2xlarge.2 (8 vCPU, 16 GB) as read back on 2026-10-09. (KB-MJY3, live, checked 2026-04-22)
- Veeam Backup & Replication 13 does not accept the backup server as the target of a disk export (the user guide gives security reasons), so a recovery chain that exports disks on TCP needs a second Windows or Linux server added to the Veeam infrastructure as the export target. (KB-NTSU, docs, checked 2026-10-09)
- Veeam v13 SureBackup has a "Backup verification and content scan only" mode that runs without a virtual lab, so it works against a backup repository hosted on TCP. (KB-OIH7, docs, checked 2026-09-02)
- The Veeam Backup & Replication 13 PowerShell reference lists Add-VBRAmazonS3CompatibleRepository, the cmdlet that adds an S3 compatible object storage repository such as OBS, for the Enterprise, Enterprise Plus and Veeam Universal License editions only, not for Standard. (KB-S7MW, docs, checked 2026-10-09)
- A Veeam perpetual per-socket licence covers only VMs running on the licensed source hosts. A workload moved to TCP leaves that socket licence behind and needs an instance-based licence. (KB-TJYJ, docs, checked 2026-09-02)
- In Veeam the storage-class selector exists only on the Amazon S3 repository type. An OBS bucket is added as the "S3 compatible with data archiving" repository type to get an archive tier. (KB-X7SP, docs, checked 2026-09-02)
- Veeam Backup & Replication 13 consumes licences only to back up data. A restore needs no licence, so restoring VMs to TCP after a disaster uses none. Backing up the restored VMs on TCP with Veeam afterwards does need licences. (KB-YQRM, docs, checked 2026-10-09)
- Each Veeam step of a disk-export recovery to TCP has a Veeam Backup & Replication 13 PowerShell cmdlet: Add-VBRAmazonS3CompatibleRepository adds the OBS bucket as an S3 compatible repository, Sync-VBRBackupRepository rescans it and Start-VBRRestoreVirtualDisks exports disks of VMware or Hyper-V backups as VMDK, VHD or VHDX. (KB-ZDJ2, docs, checked 2026-10-09)
