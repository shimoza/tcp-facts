# TCP Facts 2026-10-28: terraform

- OpenTofu 1.10.3 stores remote state on OBS through the S3 backend with the skip_ flags set. init, apply and state pull complete, and the stored state objects are byte-exact across repeated applies. (KB-23WT, live, checked 2026-07-17)
- With the opentelekomcloud Terraform provider, an opentelekomcloud_networking_secgroup_v2 resource applies in about one second and destroys in about eight seconds. (KB-2NKA, live, checked 2026-08-18)
- On a test tenant in eu-de a stale credential in terraform.tfvars took effect over the same variable supplied as a TF_VAR_ environment variable. Terraform variable precedence is -var, then *.auto.tfvars, then terraform.tfvars, then TF_VAR_, then the declared default. (KB-2NR4, live, checked 2026-08-18)
- A Terraform `count` expression that resolves to a resource attribute fails with `Invalid count argument: The "count" value depends on resource attributes that cannot be determined until apply`. The same expression is evaluated during `terraform destroy`, so the destroy is blocked as well. Counts derived from input variables are known at plan time. (KB-33BW, live, checked 2026-09-16)
- The opentelekomcloud Terraform provider 1.37.1 is licensed MPL-2.0, and hashicorp/null 3.3.0 is MPL-2.0 as well. The BUSL 1.1 licence covers the Terraform engine from version 1.6.0 onward, not the providers, with a change date four years after publication. (KB-4SPW, docs, checked 2026-09-09)
- Cloud Create (former Cloud Topology Designer) is an optional design tool that lets the customer design and deploy T Cloud Public (TCP) infrastructure and the applications on it; it stores designs and configuration data in T Cloud Public and is reached at designer.otc-service.com. (KB-75AL, contract, checked 2026-10-14)
- Terraform reserves count, for_each, depends_on, source, version, providers, lifecycle and provider as module meta-arguments. A module variable with one of those names fails during terraform init while terraform validate passes. The resource opentelekomcloud_asm_service_mesh_v1 carries an attribute named version, so a schema-driven generator hits this. (KB-A5BQ, live, checked 2026-09-16)
- The Terraform provider opentelekomcloud 1.37.9 authenticates in eu-de with AK/SK from OS_ACCESS_KEY and OS_SECRET_KEY, the project name as tenant_name and the account id in OS_DOMAIN_ID, without the account name: with those set, terraform plan got past the provider login, while a wrong access key ends in 'Incorrect IAM authentication information: ak ... not exist' (APIGW.0301). (KB-AIBN, live, checked 2026-10-06)
- After the rename to T Cloud Public the Terraform provider stays opentelekomcloud/opentelekomcloud, the API hosts stay under otc.t-systems.com and the docs stay on docs.otc.t-systems.com with sources in the opentelekomcloud-docs GitHub organisation, so existing code and identifiers stay unchanged. The docs portal pages now say T Cloud Public, while many service guides still say Open Telekom Cloud (docs mirror, checked 2026-09-25). (KB-BUGT, docs, checked 2026-09-25)
- The S3 backend option use_lockfile gives no mutual exclusion on OBS. A second apply started inside the first apply's lock window acquired the lock and exited 0, and the first apply then failed to release it. (KB-BZTT, live, checked 2026-07-17)
- The opentelekomcloud Terraform provider covers the resources around an enterprise switch build: VPC, subnet, ECS, VPC peering and the Enterprise Edition VPN stack through opentelekomcloud_enterprise_vpn_gateway_v5, opentelekomcloud_enterprise_vpn_connection_v5 and opentelekomcloud_enterprise_vpn_customer_gateway_v5. (KB-E3R7, docs, checked 2026-08-26)
- A block whose provider schema sets min_items >= 1 fails terraform validate with "Insufficient <block> blocks" when it is emitted as a dynamic block whose for_each reads an unset variable, because the count is unknown at validate time. This covers nested required blocks such as node_config then volume in opentelekomcloud_css_cluster_v1. (KB-EOI4, live, checked 2026-09-16)
- In provider opentelekomcloud the resource opentelekomcloud_ecs_instance_v1 accepts power_state, so keeping a standby instance stopped and starting it is an attribute change in the configuration rather than an imperative call. (KB-G44E, live, checked 2026-09-02)
- The opentelekomcloud provider exposes enterprise_project_id as a provider-level attribute in schema version 1.36, so the enterprise project can be set once per stack. It still takes effect only on the roughly 16 resources that are enterprise-project aware. (KB-GVDH, docs, checked 2026-07-17)
- The provider-level attributes of the opentelekomcloud Terraform provider v1.36, as listed by terraform providers schema -json, lack a default_tags block. Tags have to be set per resource, for example through a shared tagging module or variable checked by a policy test on the plan. (KB-HY3K, docs, checked 2026-07-17)
- OpenTofu 1.10.3 can keep remote state on OBS through the S3 backend with endpoint https://obs.eu-de.otc.t-systems.com and the backend's skip_* validation flags set. init, apply and state pull work and the state objects are stored byte-exact. (KB-IOPW, live, checked 2026-07-17)
- The opentelekomcloud Terraform provider reads credentials from the environment variables OS_ACCESS_KEY, OS_SECRET_KEY, OS_DOMAIN_NAME, OS_TENANT_NAME and OS_AUTH_URL, so a module whose provider block declares its own variables and one that relies on the environment can run from the same shell. (KB-J2TD, live, checked 2026-08-18)
- In provider opentelekomcloud the resource opentelekomcloud_ims_image_v2 rejects the argument backup_id with "Error: Unsupported argument". It builds an image from instance_id or volume_id, that is from a running instance or an existing volume. (KB-JM5L, live, checked 2026-09-02)
- In a live test with skip_s3_checksum unset, the OpenTofu 1.10.3 S3 backend wrote state to OBS intact: Content-Length matched the body and the object held no aws-chunked or x-amz-checksum framing. Keep skip_s3_checksum = true against future client changes. (KB-JNE2, live, checked 2026-07-17)
- In provider opentelekomcloud the resource opentelekomcloud_evs_volume_v3 accepts backup_id together with availability_zone, so a volume in another AZ can be created from a CBR backup by the resource itself with no separate API call. Checked with terraform validate against the schema, not with an apply. (KB-JQR6, live, checked 2026-09-02)
- An auto-loaded terraform.tfvars overrides a TF_VAR_ environment variable of the same name, so a credential left in a tfvars file keeps being used after the environment export is changed. (KB-L375, live, checked 2026-08-18)
- The opentelekomcloud Terraform provider authenticates with an access key and secret key together with domain_name, tenant_name and auth_url. (KB-L7RI, docs, checked 2026-09-25)
- In the opentelekomcloud Terraform provider, enterprise projects are set through the enterprise_project_id argument on about 16 resource types, for example opentelekomcloud_vpc_secgroup_v3, where the argument is ForceNew. (KB-LVIQ, live, checked 2026-06-03)
- Terraform provider opentelekomcloud version 1.37.7, published 2026-08-27, exposes 331 resources. (KB-LYTV, live, checked 2026-09-02)
- The schema of the Terraform provider opentelekomcloud 1.37.9 still lists five resource types of VBS and CSBS (opentelekomcloud_vbs_backup_v2, _vbs_backup_policy_v2, _vbs_backup_share_v2, _csbs_backup_v1, _csbs_backup_policy_v1), although both services are no longer available since 01.01.2026. A resource type in the provider schema does not make a service offered. (KB-M6LM, live, checked 2026-10-12)
- Provider opentelekomcloud covers cbr_vault_v3 and cbr_policy_v3, compute_volume_attach_v2 and the SDRS set sdrs_protectiongroup_v1, sdrs_protected_instance_v1, sdrs_replication_pair_v1 and sdrs_replication_attach_v1. In cbr_policy_v3 consistent_level defaults to crash_consistent, which matches what the CBR API returns. (KB-PGPD, live, checked 2026-09-02)
- Terraform's indented heredoc <<- strips the smallest indentation found on any non-empty line of the body. A nested heredoc whose interpolation and terminator lines sit at column 0 sets that baseline to 0, so the whole body keeps its indentation and the shebang arrives indented. (KB-PQ4E, live, checked 2026-08-18)
- State written to OBS by OpenTofu 1.10.3 without skip_s3_checksum carries no aws-chunked or x-amz-checksum framing: Content-Length equals the body and the object reads back as valid JSON. (KB-R5TS, live, checked 2026-07-17)
- The opentelekomcloud Terraform provider exposes enterprise projects through the enterprise_project_id argument on about 16 resources, among them vpc_secgroup_v3, lts_group_v2, fgs_function_v2, ces_*, private_nat_*, taurusdb_*, apigw_gateway_v2, cfw_firewall_v1 and waf_cloud_instance_v1. (KB-RE2U, docs, checked 2026-06-02)
- The Terraform resource opentelekomcloud_ecs_instance_v1 resizes in place on a flavor change, stop, resize and start, with no rebuild, and it ignores the image cond:image tag like the raw API does. Verified from s7n.large.4 to s9.large.2 on an untagged image. (KB-T2RV, live, checked 2026-07-21)
- On 2026-10-05 the upstream Terraform issue 36704 (skip_s3_checksum not applied to GetObject, a breaking change since Terraform 1.11.2 for S3-compatible state backends) was still open. A remote state in OBS therefore still needs Terraform pinned to 1.11.1 or OpenTofu 1.10 or newer with the skip flags and use_lockfile. (KB-TN3S, docs, checked 2026-10-05)
- The opentelekomcloud Terraform provider (schema v1.36) accepts enterprise_project_id at provider level, so one enterprise project can be set once per stack instead of on every resource. It only takes effect on resources that support enterprise projects. (KB-U52F, docs, checked 2026-07-17)
- Resource Formation Service (RFS) is a managed infrastructure-as-code engine that builds and manages cloud resources such as databases, VPCs, pipelines and IAM roles from templates, in batches and in a consistent way. The documentation states that RFS fully supports Terraform, both the HCL language and providers, and deploys the resources a template specifies automatically. (KB-UJSI, contract, checked 2026-10-14)
- T Cloud Public (TCP) supports infrastructure as code: Resource Formation Service (RFS) runs Terraform templates (HCL and providers) as a managed service, the opentelekomcloud Terraform provider (version 1.37.7 exposes 331 resources, KB-LYTV) drives the platform from customer pipelines, and resources are provisioned and managed fully automatically through the platform APIs, the OpenStack APIs and standard OpenStack command-line tools. (KB-V42N, docs, checked 2026-10-11)
- With OpenTofu 1.10.3, use_lockfile = true on an OBS S3 backend gave no mutual exclusion in a live test: a second concurrent apply took the lock and overwrote the .tflock file. Serialize applies in the pipeline or use a backend with real locking. (KB-VSJN, live, checked 2026-07-17)
