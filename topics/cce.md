# TCP Facts 2026-10-12: cce

- Cloud Container Engine and Cloud Container Engine Turbo (CCE, CCE Turbo) provide managed Kubernetes clusters in which the customer runs, manages and monitors containers, with the compute, storage and network resources reserved on T Cloud Public (TCP). CCE Turbo adds passthrough networking (Cloud Native 2.0) and better scheduling compared with CCE Standard; the preassembled cluster flavors hold up to 50, 200, 1,000 or 2,000 nodes, among them a high-availability flavor. The Regions and Endpoints page lists API endpoints for CCE in eu-de and eu-nl. (KB-22XD, contract, checked 2026-10-11)
- A new CCE cluster comes with 17 storage classes, among them `csi-disk`, `csi-nas`, `csi-obs`, `csi-sfsturbo` and older flexvolume ones, and none of them carries the `storageclass.kubernetes.io/is-default-class` annotation. A PersistentVolumeClaim that does not name a class stays Pending. (KB-27TG, live, checked 2026-09-16)
- CCE Turbo clusters (Cloud Native Network 2.0) are documented and orderable on TCP through cluster category Turbo, containerNetwork mode eni and an eniNetwork block in the create-cluster API, and add per-pod security groups and ELB passthrough. (KB-2HZA, docs, checked 2026-09-25)
- GP SSD v2 (GPSSD2) is valid for CCE persistent volumes through the everest CSI driver on TCP, eu-de, and is set in the StorageClass. (KB-3DQF, docs, checked 2026-09-09)
- A live price API query for cce returned only s1 and s2 cluster management items, with no line for the Turbo variant. (KB-3UFL, live, checked 2026-09-24)
- CCE publishes https://<cluster-uid>.cce.eu-de.otc.t-systems.com in status.endpoints as external_otc. The name resolves to the platform API gateway and serves a valid certificate even when no elastic IP is bound to the cluster API. (KB-4Z2W, live, checked 2026-09-16)
- GET /api/v3/clusterupgradepaths on the CCE endpoint needs no cluster id and returns the upgrade targets per cluster version and platform version, a call the CCE API reference in the docs mirror does not list. On 2026-09-25 it offered v1.30 clusters on platform version cce.14.70 or cce.14.72 an upgrade to v1.31.14-r32, and older v1.30 platform versions only the patch v1.30.14-r72. (KB-5BJH, live, checked 2026-09-25)
- CCE nodes join a cluster with no internet egress, because bootstrap and add-ons come from internal endpoints. A pod pulling an image from a public registry then stays in ImagePullBackOff. One NAT gateway with an SNAT rule covers the whole node subnet. (KB-5IOB, live, checked 2026-08-18)
- The CCE Kubernetes version policy in the docs mirror (commit of 2026-08-31) lists v1.30 to v1.34 as in commercial use, with end of service in November 2026 for v1.30, June 2027 for v1.31, October 2027 for v1.32, March 2028 for v1.33 and July 2028 for v1.34. v1.29 reached end of service in June 2026. (KB-5TID, docs, checked 2026-09-25)
- A CCE cluster with container_network_type overlay_l2 rejects an Ubuntu 22.04 node pool on versions v1.31 through v1.34 with 403 CCE.01403001, "Not support Ubuntu 22.04 in overlay_l2 cluster". EulerOS 2.9 and HCE OS 2.0 are accepted there, spelled that way in the API body. (KB-6O6J, live, checked 2026-09-16)
- On a CCE worker the kubelet reports `nodefs` of about 10 GiB, with allocatable ephemeral-storage 9.8 GiB, even on a 50 GiB system disk. Images and container layers sit on the data disk as `imagefs`, 88 GiB on a 100 GiB volume. Everything under /var/lib/kubelet, including every emptyDir, uses the small nodefs. (KB-75DH, live, checked 2026-09-17)
- In a CCE cluster with the VPC or tunnel network, traffic from a pod to an external overlay relay leaves through the node, so a relay port such as UDP 9993 for ZeroTier must be allowed in the node security group only if its default allow-all outbound rule was hardened. In a CCE Turbo cluster the ENI security group governs pod egress instead. (KB-76SZ, docs, checked 2026-09-25)
- GET /api/v3/projects/{project_id}/clusters returns the CCE clusters of a project and answers with an empty list when none exist. (KB-7CH3, live, checked 2026-09-16)
- The Python kubernetes client method CoreV1Api.read_namespaced_pod_log with the default _preload_content=True returns a str holding the repr of the response bytes (b'...\n...'). Passing _preload_content=False and decoding resp.data gives the raw log text. (KB-AUZM, live, checked 2026-09-17)
- On 2026-09-25 the CCE upgrade path API listed cluster version v1.35 (latest patch v1.35.3-r4) in eu-de and eu-nl, and most CCE add-on templates declared support for v1.35, although the version policy in the docs mirror ends at v1.34. No v1.34 platform version had v1.35 as an upgrade target yet. (KB-BB4E, live, checked 2026-09-25)
- ECS instances serving as CCE worker nodes carry the string tags CCE-Cluster-ID and CCE-Dynamic-Provisioning-Node. The CCE node field status.privateIP equals the Kubernetes node name, which joins the ECS view to the CCE view. (KB-BHHR, live, checked 2026-09-17)
- The node security group that CCE creates already allows the node port range 30000-32767, so the load balancer reaches a NodePort Service over the node address with the default rules. (KB-C5QV, live, checked 2026-09-16)
- A managed CCE cluster can have worker nodes with no SSH access. Host-level software is then installed from inside the cluster by a privileged pod that runs in the host namespaces. (KB-CGCI, live, checked 2026-02-04)
- On CCE a 10 Gi PersistentVolumeClaim with the csi-disk storage class bound in about one minute. While the volume is being provisioned, exec into the pod answers "container not found". (KB-CR6R, live, checked 2026-09-17)
- CCE creates the SWR pull credential default-secret in every namespace of a cluster, so a Pod or Job pulling a private image from SWR only needs imagePullSecrets: [{name: default-secret}]. (KB-E6ID, live, checked 2026-09-17)
- CCE Turbo node pools accept x86 VM flavors from the c3n, c4ne, c7n, c9, x2ne, s7n, s9, m3n, m7n and m9 families plus the GPU families g7, pi5e and p5e, as the CCE API reference lists them on 2026-09-25; region availability varies. (KB-GMRI, docs, checked 2026-09-25)
- GET /api/v3/addontemplates on the CCE endpoint returned 14 add-on templates on eu-de on 2026-09-25: autoscaler, cce-hpa-controller, metrics-server, nginx-ingress, gpu-beta, volcano, coredns, everest, grafana, log-agent, npd, storage-driver, node-local-dns and cie-collector. The newest supportVersions patterns reach cluster version v1.35. (KB-I7J7, live, checked 2026-10-05)
- On CCE, `csi-disk` is the EVS-backed block storage class, and a 10Gi PersistentVolumeClaim naming it bound in about 5 seconds. (KB-JGA2, live, checked 2026-09-16)
- While no elastic IP is bound to the CCE cluster API, the external_otc endpoint cannot be authenticated against, although it resolves and serves a valid certificate. (KB-KTT2, live, checked 2026-09-16)
- Pod density on a CCE Turbo node is capped by the node flavor's supplementary network interface quota rather than by the kubelet default. Documentation examples give 128 pods on a 4xlarge class node and 256 on an 8xlarge class node. (KB-NFSU, docs, checked 2026-06-12)
- Application Service Mesh (ASM) is a managed service mesh compatible with Kubernetes and Istio that manages the lifecycle and traffic of microservices without changes to the application. It provides load balancing, outlier detection and fault injection, and grayscale releases such as canary and blue-green deployment. The Regions and Endpoints page lists the ASM API endpoint in eu-de. (KB-NMSH, contract, checked 2026-10-11)
- GET /api/v3/projects/{project_id}/clusters on the CCE endpoint answers HTTP 200 with a payload of kind Cluster, apiVersion v3 and an items array. The call is AK/SK signed like other platform APIs. (KB-NOWE, live, checked 2026-07-02)
- T Cloud Public (TCP) offers managed Kubernetes in Cloud Container Engine (CCE), as CCE Standard and CCE Turbo clusters, with Kubernetes v1.30 to v1.34 in commercial use per the version policy in the documentation mirror of 2026-08-31 (KB-5TID). Clusters use ECS nodes, VPC, ELB and EVS, SFS or OBS storage, and container images come from Software Repository for Containers. (KB-OOVV, docs, checked 2026-10-11)
- Ubiquitous Cloud Native Service (UCS) is a platform that centrally manages distributed Kubernetes clusters, so cloud-native applications run across regions and clouds, on CCE and CCE Turbo clusters of T Cloud Public (TCP) as well as on Kubernetes clusters of other cloud vendors, with traffic distribution between them. The service description of 17.08.2026 announced it as expected to be available from 1 September 2026. (KB-P3JV, contract, checked 2026-10-11)
- When concurrent emptyDir-heavy pods fill nodefs on a CCE worker, the node gets `node.kubernetes.io/disk-pressure` and further pods stay Pending with an untolerated taint. `GET /api/v1/nodes/<node>/proxy/stats/summary` can report 5 percent used while the taint is still set, because the kubelet holds the condition for its transition period. (KB-QYGN, live, checked 2026-09-17)
- On a standard CCE cluster a LoadBalancer ingress registers only Services of type NodePort. With a ClusterIP backend the controller logs `can not found protocol port of pod <ns>/<pod>, skip add member`, the ELB pool stays empty and requests return 502. ClusterIP backends work on a CCE Turbo cluster with a dedicated load balancer. (KB-SH6U, docs, checked 2026-09-16)
- The public price API carries the CCE cluster charge under sn=cce as one hourly item per cluster flavor: cce.s1.small, cce.s1.medium and, for the HA clusters, cce.s2.small to cce.s2.xlarge, six items in eu-de on 2026-09-24. Worker nodes, EIP, NAT gateway and EVS are priced under their own service names. (KB-SJJV, live, checked 2026-09-24)
- The CCE add-on catalog read on eu-de on 2026-09-25 held no keda and no knative template, so on that date no add-on offered request driven pod scale to zero. (KB-SQ4W, live, checked 2026-10-05)
- The number of master nodes in a CCE cluster is fixed when the cluster is created, so a highly available control plane has to be chosen at creation time. (KB-UOZO, docs, checked 2026-09-25)
- On CCE the number of master nodes is fixed at cluster creation. Changing the cluster scale (50, 200, 1000 nodes) leaves the master count unchanged and only moves upward, so reaching a three-master HA cluster from a single-master one means a new cluster. (KB-VXRJ, docs, checked 2026-09-09)
- A stale `node.kubernetes.io/disk-pressure` taint is removed with `kubectl taint node <node> node.kubernetes.io/disk-pressure-`; Kubernetes adds it again automatically while the node disk space is still near its limit. (KB-WJEE, docs, checked 2026-09-25)
- The hashicorp/kubernetes provider for a CCE cluster must be configured from state written by an earlier apply, read through terraform_remote_state plus base64decode of certificate_clusters and certificate_users from opentelekomcloud_cce_cluster_v3. Providers are configured before resources created in the same apply exist. (KB-WPTN, live, checked 2026-08-18)
- The CCE version policy says the console creates clusters only of the latest two commercial versions (v1.33 and v1.34) and that v1.30, v1.31 and v1.32 clusters are created only through the API, while the create-cluster API reference says the console offers the latest three versions. (KB-XVNK, docs, checked 2026-09-25)
- When a CCE cluster version reaches end of service, CCE stops creating new clusters of that version and ends technical support, vulnerability fixes, patches and the CCE SLA for clusters that still run it. (KB-Z6PU, docs, checked 2026-09-25)
- GET /api/v3/projects/{project_id}/quotas on cce.eu-de.otc.t-systems.com returns the CCE quota. On a test project the read showed a limit of 5 clusters per region on that date. (KB-ZZK5, live, checked 2026-08-18)
